# Pizza Tasty

Mobile-first restaurant ordering **prototype** for Pizza Tasty: menu, product customisation,
cart, dine-in / takeaway / delivery checkout through WhatsApp, reservations, in French,
English and Spanish.

> **Demo data only.** The menu, prices, hours, address, offers and food illustrations are
> placeholders. Nothing is sent anywhere: the WhatsApp step and the reservation form end in
> clearly labelled demo states. The site is `noindex`.

Live preview: https://pizzatasty-demo.vercel.app

## Run it

```bash
npm install
npm run dev          # http://localhost:3000 → redirects to /fr
npm run build        # production build (all pages are static)
npm run typecheck
npm run art          # regenerate the demo food illustrations into public/food
```

Node 22.

## Where things live

| Path | What it is | Replace when real data arrives |
|---|---|---|
| `src/config/restaurant.ts` | Restaurant facts: hours, time zone, currency, delivery rules, WhatsApp number, phone, address | **Yes.** Setting `whatsappNumber` turns on real WhatsApp hand-off; setting `phone` and `address` turns on the call and directions buttons |
| `src/content/demo/menu.ts` | Categories, products, sizes, option groups, prices (cents), badges, availability | **Yes:** swap for real content, or a CMS adapter returning the same `Menu` type |
| `public/food/*.svg` | Illustrated placeholders, generated by `scripts/food-art/` | **Yes:** drop in real photos and update `image` in the menu |
| `src/i18n/dictionaries/{fr,en,es}.ts` | Interface text. EN/ES are type-checked against FR, so a missing key fails the build | Copy edits only |
| `src/domain/` | Pure logic: pricing, cart reducer, totals and delivery rules, WhatsApp message, opening hours, search, validation | No |
| `src/components/` | UI: header, product card and sheet, cart and checkout, menu browser, reservation form, home sections | No |
| `src/app/[locale]/` | Routes: `/fr`, `/en`, `/es` + `/menu`, `/reservation` | No |

## How it works

- **Static pages, small client islands.** Every page is pre-rendered HTML. JavaScript is used
  where state lives: cart, product sheet, search, forms.
- **The cart stores choices, not prices.** Prices are always recomputed from the menu, so a
  price change or a sold-out item is caught at once. Money is integer cents.
- **Only lines and order mode are saved** in `localStorage`. The customer's name, phone and
  address never are.
- **WhatsApp message** (`src/domain/order-message.ts`): plain text in the staff's language with
  an order reference. It's built by a pure function, ready for a real number.
- **Sheets are native `<dialog>`.** They get focus containment, Esc to close and focus return
  from the browser.
- **Open/closed status** is computed in the browser, in the restaurant's time zone, never baked
  into cached HTML.
